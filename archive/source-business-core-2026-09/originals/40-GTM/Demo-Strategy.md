# Demo Strategy

## Purpose

This draft file describes the current direction for demos in GTM. It does not own Client evidence, promise outcomes, or define a preferred tool.

- Show an end-to-end business problem being solved, not technology for its own sake.
- Keep each demo focused on the operational point being communicated.
- Use the narrative: Before → Problem → System intervention → Result.
- Distinguish a demonstration from validated Client proof.
- Store reusable demo assets in `60-Assets/Demos/` and link them rather than duplicating them.
- Apply [[Solution-Selection]] and [[Tool-Selection]]; a demo must not create a tool-first recommendation.

Demos support [[Founder-Content]], relevant outreach, and earned trust in [[Sales-Funnel]]. Do not finalize the demo portfolio yet.
