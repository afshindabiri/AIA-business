# Post-Implementation Operations

## Purpose

This file owns the operational boundaries after Handover. It does not own commercial pricing or assume ongoing support is included.

## Distinctions

- **Stabilization:** part of implementation delivery before Acceptance and Handover; it resolves delivery issues and is not ongoing maintenance.
- **System Care:** optional ongoing operational care for an implemented system.
- **Continuous Improvement:** optional evidence-led identification and delivery of ongoing improvements.

Define ownership, operational boundaries, response expectations, exclusions, and review points for each Client engagement. Do not silently extend implementation obligations into indefinite support.

Do not merge Stabilization with maintenance.

## System Care Project boundary

Apply the canonical engagement-boundary rules in [[Customer-Lifecycle#Project / engagement boundary]]. System Care that creates an independent ongoing obligation or lifecycle after an Implementation Project closes is a separate Project/Cycle under the same Client; it must not silently extend the completed Implementation Project indefinitely.

Do not create monthly Projects for ongoing care. One System Care Project may remain active for its agreed service period, and a new Implementation Project may coexist with it. Do not create a dedicated System Care template until a real operational need justifies one.
